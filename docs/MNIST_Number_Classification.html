Introduction

In class we have gone through the process of a creating a classifier to distinguish a 2 from 7 by using some predefined features, which correspond to the proportion of dark pixels in different quadrants of an image. Is there a solid way to classify between the numbers? It might be easy to distinguish these two numbers if it were just one person’s handwriting. However, we want to create a classifier such that we are able to distinguish between these two numbers given a large set of handwritten numbers. With everyone having their own distinct way of writing, how are we able to create a general classification such that we are able to distinguish between the 10 numbers? We are interested in distinguishing between the digits of 5 and 7. To do this, we have to create a classifier, which distinguishes a 5 from 7 by using some predefined features, which corresponds to the proportion of dark pixels of an image. In this challenge we will be using the mnist dataset to create an end-to-end classifier that distinguishes between two digits 5 and 7.

Image dataset

We begin our analysis with importing the mnist dataset, which includes 60,000 rows, which corresponds to 60,000 different handwritten digits. However, this takes up a lot of memory, so we decided to include the first 1000 rows in our initial analysis. Note how we use the function slide_head(n=1000) to grab the first 1000 rows of the mnist dataset. We call this new dataset mnist_5_7.

Our new dataset of mnist5_7 has 1000 observations and 875 variables. The first variable, digit, corresponds to what number is represented. The rest of the columns, V1:V784 correspond to the gray-scale values of each of the pixels from a 28 by 28 image.

Region description

A region of an image can be defined by a 28 by 28 matrix of 0s and 1s, which can be represented as a text file where the rows are separated by “,” and where columns occur in different lines. For our regions selection, we wanted to be more creative and at the same time efficient so to maximize the area covered by both our digits 5 and 7 but minimizing the overlap. For region1, which represents digit 5, we’ve created a shape that intriguingly resembles the digit 7. This is a creative approach on our side because while the digit 5 has a different structure, by using the negative space of 7 we’re effectively creating a complementary shape that does not overlap with the actual 7 digit. Whereas, For region2, representing digit 7 to take a staggered form that extends diagonally across the matrix we aimed at creating a boomerang looking shape or a staircase shape to cover the distinctive features of the digit 7, like its horizontal line on the top and the angular line descending to the right. This pattern would occupy spaces that are less likely to be filled by the digit 5, which typically has a horizontal line at the lower part and a curve at the top right. Hence, for region2, the selection ensures that the main structural elements of 7 are highlighted without encroaching on the areas where 5 would be prominent.

Notice we are using col_names=FALSE, since region1.csv and region2.csv do not have column names.

Auxiliary functions (part 2)

Let’s define and use plot_region to see how this region looks. The function plot_region below is designed to visualize regions represented as binary matrices. It takes a single argument tbl, which is expected to be a table of values. Inside the function, this table is converted into a matrix and the values are multiplied by 128, suggesting that the binary 0 or 1 values in tbl are scaled up to create a grayscale image with pixel values of either 0 or 128. Then, the function image is used to display this matrix. However, before the matrix is passed to the image function, it is transposed using the t() function and then flipped along the vertical axis (as indicated by the [28:1] indexing), which effectively rotates the image for proper orientation. The purpose of this function is to plot the region of a digit from a 28 by 28 matrix, where the digit’s shape is represented in a format suitable for image display in R.

plot_region <- function(tbl) {
  digit_mat <- as.matrix(tbl)*128 # Convert tbl into matrix and assign gray=128

  image(t(digit_mat)[,28:1]) #Plot the image making sure is rotated
}

Now, given an image and a region, we would like to calculate the proportion of dark pixels of the image in the region. We can do that using the function calc_prop(). The calc_prop function is designed to determine the proportion of dark pixels within a certain region of an image. It takes a predefined region matrix where the value 1 indicates the relevant region, and a row vector representing pixel data from an image. The region matrix is rotated and flipped to align with the MNIST dataset’s image orientation. Next, the row vector is converted into numerical form, if it isn’t already, and reshaped into a 28x28 pixel matrix that represents the image, known as digit_mat. The function then identifies which pixels fall within the specified region and assesses whether these pixels are dark based on a threshold value (greater than 20 out of 255 in grayscale). It counts the dark pixels and calculates their proportion within the selected region, which is then returned as the output. This method is generally useful in image processing tasks where the density of dark pixels within specific areas needs to be analyzed, such as in handwriting recognition here.

calc_prop <- function (region, row) {
  # Rotate "region" so is in same order as mnist images
  region <- t(as.matrix(region))[,28:1]
  # Take row from mnist and transform into a "digit" matrix
  digit_mat <-  row |>
    as.numeric()|>
    matrix(nrow = 28)
  # Find positions of pixels from "region"
  pos = (region==1)
  # Subset "digit" to the positions and count dark pixels (grey>20)
  dark = digit_mat[pos]>20 
  # Return proportion of dark pixels of "image" in "region"
  return(sum(dark)/sum(pos))
}

We’ve chosen two contrasting models: K-Nearest Neighbors (KNN) and Logistic Regression. The rationale for this choice lies in the complementary nature of the decision boundaries that each model constructs.KNN makes custom-fit decisions by closely examining its nearest data points. Its ability to capture the nuanced, subtle patterns in the dataset by considering the proximity of its neighbors makes it an excellent candidate for when the relationships within the data are complex and interwoven. Logistic Regression, on the other hand, takes on the role of a cartographer, drawing straight-line boundaries to divide the dataset into classes. Its strength lies in its straightforward approach, making it ideal for situations where a linear relationship does a good job of separating the classes. Choosing these two models allows us to explore and understand our dataset from two different perspectives: one that is intricately detailed and another that is elegantly straightforward. By comparing their performance, we hope to gain a deeper insight into the nature of our data and can make a more informed decision on which model best captures the underlying relationships between our variables.

KNN

For our second model we developed a K-Nearest Neighbors (KNN) classification model using auxiliary functions and the determination of the optimal number of neighbors (K) to ensure the best possible model accuracy. Firstly, we established auxiliary functions that allow us to generate and assess the KNN model systematically. The create_knn function is designed to take in a specified number of neighbors (K) and a dataset, using these parameters to build a KNN model for classification purposes by we specifying the KNN algorithm, the mode of the model (classification), and the formula that describes the relationship between predictors and outcome digit here. A function named calc_accuracy, which serves to evaluate the performance of our KNN model. It predicts the classes for a given dataset and then compares these predictions to the true labels to calculate the accuracy of the model. The following code creates a KNN model.

#KNN model generalized
# Creates a KNN classification model
create_knn <- function(k, tbl) {
  knn_spec <- nearest_neighbor(neighbors = k) %>%
    set_mode("classification") %>%
    set_engine("kknn")

  knn_recipe <- recipe(digit ~ prop1 + prop2, data=tbl)
  
  knn_wflow <- workflow() %>%
    add_recipe(knn_recipe) %>%
    add_model(knn_spec)
  
  knn_model <- fit(knn_wflow, tbl)
  return(knn_model)
}

KNN Accuracy function –auxiliary function

calc_accuracy <- function(knn_model, tbl) {
  predictions <- predict(knn_model, tbl)$.pred_class
  true_labels <- tbl$digit
  mean(predictions == true_labels)
}

In order to identify the optimal number of neighbors, we utilized a loop that iterates through a range of K values from 1 to 210 with a difference of 4. For each iteration, we generate a KNN model using our create_knn function and then compute its accuracy on a test dataset using the calc_accuracy function. The results are collected in a table that maps each K value to its corresponding accuracy.

Finding K optimal value:

The confusion matrix for the (KNN) prediction of digits 5, 6, and 7 above suggests that there is a notable level of confusion between the digits 5 and 6. This pattern of confusion could potentially be attributed to the similar shapes and strokes involved in writing these two digits. For instance, both digits have a round component—the lower half of ‘5’ and 6’. When written quickly or with a particular style, the distinction between the two can become blurred. Additionally, the top part of a ‘5’ can sometimes resemble the loop of a ‘6’, especially if the ‘5’ is not properly closed or the ‘6’ is loosely written. Also, it is worth noting that 6’s tend to get misclassified more often than either 5’s or 7’s.
